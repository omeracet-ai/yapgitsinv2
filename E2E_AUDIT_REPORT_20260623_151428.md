## [CRITICAL] Akış #15: XSS payload stored verbatim in `/jobs` POST
**Adım:** Authenticated user posts a job with `title:"<script>alert(1)</script>"` and `description:"<img src=x onerror=alert(1)>"`
**Beklenen:** HTML escaped or stripped at validation; min length check rejects script-only title
**Gerçekleşen:** Stored as-is, returned in `GET /jobs` to all clients. Flutter `Text()` is safe by default, but Next.js admin panel + any future web preview is vulnerable. Also XSS could land in Admin Panel job-detail HTML.
**Endpoint/Dosya:** `nestjs-backend/src/modules/jobs/dto/create-job.dto.ts` (no `class-sanitizer` / HTML strip)
**Repro:**
```bash
curl -A "Mozilla/..." -H "Authorization: Bearer $JWT" -X POST https://api.yapgitsin.tr/jobs \
  -H "Content-Type: application/json" \
  -d '{"title":"<script>alert(1)</script>","description":"<img src=x onerror=alert(1)>","category":"Temizlik","location":"İstanbul","budgetMin":100,"budgetMax":500}'
```
Created job id `1ffce62e-63ff-49dc-a023-0abe41059b19` with literal script in title. (Already deleted as cleanup.)
**Fix önerisi:** Add `@Transform(({value}) => sanitizeHtml(value, {allowedTags:[]}))` to all free-text DTO fields (title, description, message). Or globally `class-transformer` + DOMPurify-equivalent.

## [CRITICAL] Akış #15: UTF-8 encoding broken — "İstanbul" → "�stanbul"
**Adım:** POST `/jobs` with `location:"İstanbul"`; read back via GET
**Beklenen:** UTF-8 preserved
**Gerçekleşen:** The literal `İ` (U+0130) is mangled to `�` in the response body, meaning either the response encoding header omitted charset or the entity column is single-byte. Other Turkish text already in DB (older rows with `Üsküdar`) renders OK, so this is a **regression** in the create-flow path. Possibly the controller is reading `req.body` as latin1, or `class-validator` `@IsString()` going through a buggy `@Transform`.
**Endpoint/Dosya:** `jobs.controller.ts` POST, possibly multer body parser fallthrough
**Repro:** Same XSS curl above; check `location` field of response.
**Fix önerisi:** Verify `app.use(express.json({type:'application/json'}))` order, ensure no upstream nginx rewrites charset, force `Content-Type: application/json; charset=utf-8`. Add Cypress e2e for Turkish chars in all DTO fields.

## [HIGH] Akış #1: Auth register throttle is harsh and silently inconsistent with headers
**Adım:** First 3 unsuccessful registers (validation errors) still count toward the 3/hour `auth-register` quota, locking the IP out from ALL register attempts for an hour
**Beklenen:** Either count only successful registers, or return a clear `Retry-After` in seconds (currently `Retry-After-Auth-Register: 3474` is non-standard header name; clients won't honor it)
**Gerçekleşen:** Standard `X-Ratelimit-Limit-Auth-Register: 1000000` header reported in successful responses (misleading: the actual limit applied is 3/hr from `@Throttle` decorator)
**Endpoint/Dosya:** `auth.controller.ts:118` `@Throttle({ 'auth-register': { limit: 3, ttl: 3_600_000 } })`; ThrottlerModule global guard reports default `1M` because the named bucket isn't surfaced on the headers
**Fix önerisi:** Skip throttle on 400 (validation) responses, only debit on 201. Use standard `Retry-After: <seconds>` and remove non-standard `-Auth-Register` suffix. Improve header truthfulness.

## [HIGH] Akış #14: Helmet/CSP misconfig — `unsafe-inline` script-src + missing `nonce`
**Adım:** Read CSP header from `/health`
**Gerçekleşen:**
`script-src 'self' 'unsafe-inline' blob: https://www.googletagmanager.com https://plausible.io`
The `'unsafe-inline'` makes the XSS finding above directly exploitable in any web view. Also `frame-src 'self' https://sandbox-api.iyzipay.com https://api.iyzipay.com` mixes sandbox+prod — the sandbox frame can MITM payments if hijacked.
**Fix önerisi:** Move to nonce-based CSP (Helmet `contentSecurityPolicy.useDefaults` + per-request nonce). Drop `unsafe-inline`. Remove sandbox iyzipay from prod CSP — conditional on `NODE_ENV !== 'production'`.
